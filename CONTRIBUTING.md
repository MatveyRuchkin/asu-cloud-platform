# Как работать в команде

> **Впервые на GitHub?** Начните с [пошаговой инструкции](docs/START_HERE.md) — она описывает каждый экран, клик и действие. Для работы без обязательной платной подписки смотрите [OpenCode](docs/OPENCODE.md).

## Самое важное
Репозиторий: **MatveyRuchkin/asu-cloud-platform**. Сайт персональных задач и ролей публикуется через GitHub Pages. **Никогда не отправляйте готовый код только в Telegram:** сдача работы — через GitHub Pull Request.

1. Найдите себя на сайте и откройте ссылку на свою Issue. Если роли назначены неверно — сообщите PM.
2. Прочитайте README.md, AGENTS.md, docs/architecture.md и docs/api/openapi.yaml. Общий контракт пока является черновиком.
3. **Закрепите свою задачу за собой:** на персональной странице нажмите **«Открыть Issue #…»**, войдите в GitHub, прокрутите задачу вниз к полю **Add a comment**, введите `беру` и нажмите **Comment**. Бот [Issue Claim Bot](https://github.com/MatveyRuchkin/asu-cloud-platform/blob/main/.github/workflows/claim.yml) попытается назначить вас исполнителем (**Assignees**) и поставить метку **`status: taken`**. Проверьте, что ваше имя появилось в Assignees. Если бот отвечает, что назначение невозможно, обратитесь к PM: вероятно, вас нужно пригласить в репозиторий. **Не забирайте чужие персональные задачи.** Пока одна задача на человека.
4. Сделайте Fork репозитория на свой GitHub-аккаунт. `git clone https://github.com/ВАШ_ЛОГИН/asu-cloud-platform.git`.
5. `cd asu-cloud-platform && git remote add upstream https://github.com/MatveyRuchkin/asu-cloud-platform.git`.
6. `git fetch upstream dev && git switch -c feature/НОМЕР upstream/dev` — так вы гарантированно начинаете с актуальной ветки `dev`.
7. Вносите изменения только по своей задаче, проверяйте результат и коммитьте в ветку.
8. `git push -u origin feature/НОМЕР`. В GitHub создайте PR: base = **MatveyRuchkin/asu-cloud-platform:dev**, compare = ваша ветка форка.
9. В описании PR обязательно напишите `Closes #НОМЕР`, что изменено и как проверить. Учтите: если PR влит только в `dev`, GitHub может не закрыть Issue автоматически — статус подтверждает reviewer.
10. После замечаний исправьте ту же ветку и обновите PR. Новая задача после закрытия текущей.

## Нейросети
Можно пользоваться ChatGPT, Codex, OpenCode или работать самостоятельно. Подписка Codex не обязательна. OpenCode бесплатен как программа, но отдельные модели могут быть платными — смотрите [инструкцию](docs/OPENCODE.md). ИИ не заменяет проверку результата. Передавайте нейросети ссылку на Issue, файлы с инструкциями и контракты; не позволяйте ей придумывать новые поля и библиотеки без согласования.

## Что делать без опыта
Скопируйте промпт из docs/tasks/ВАШ_КОД.md и попросите ИИ разъяснить каждый шаг. Если задача зависит от незавершённой архитектуры, начинайте с макета/схемы/списка вопросов, а не произвольного кода.

## Права и безопасность
PR не вливается без review. Не публикуйте секреты и данные реальных студентов. При обнаружении случайно опубликованного секрета сообщите Tech Lead и немедленно отзовите секрет.
