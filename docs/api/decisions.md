# API-01 — журнал решений

## Статус

Контракт остаётся **черновиком**. Этот файл фиксирует исходную точку для
ревью, но не заменяет подтверждение backend, frontend, БД и QA. Пока
подтверждений нет, зависимые модули не должны считать новые маршруты или поля
утверждёнными.

## Зафиксированные правила

Следующие правила уже определены в `docs/architecture.md` и отражены в
`openapi.yaml`:

- API использует REST и JSON в UTF-8 с префиксом `/api/v1`;
- JSON-поля именуются в `snake_case`;
- идентификаторы передаются строками UUID;
- даты, когда они появятся в схеме, передаются в ISO 8601 UTC;
- отсутствующая цена или ссылка обозначается `null`; цена — `price_rub` в
  целых рублях;
- защищённые операции используют Bearer JWT;
- публичные операции явно содержат `security: []`, чтобы инструменты OpenAPI
  не приняли отсутствие требования авторизации за пропуск в спецификации;
- тело ошибки имеет вид `Error`: обязательные `code` и `message`,
  необязательный объект `details`.

## Текущая матрица контракта

Таблица ссылается на имена схем из `openapi.yaml`: они являются точным
источником полей, типов и обязательности.

| Область | Маршрут и метод | Вход | Успешный ответ | Ошибки / доступ |
| --- | --- | --- | --- | --- |
| Состояние сервиса | `GET /health` | — | `200` с `{status}` | публичный |
| Регистрация | `POST /auth/register` | `RegisterRequest` | `201` с `User` | `400` с `Error`, публичный |
| Вход | `POST /auth/login` | `LoginRequest` | `200` с `Token` | `401` с `Error`, публичный |
| Профиль | `GET /users/me` | — | `200` с `User` | Bearer JWT; `401` с `Error` |
| Университеты | `GET /universities` | — | `200` с массивом `University` | публичный |
| Объявления | `GET /ads` | `category_id`, `university_id` в query | `200` с массивом `Ad` | публичный |
| Создание объявления | `POST /ads` | `AdCreate` | `201` с `Ad` | Bearer JWT; `401` с `Error` |
| Разделы форума | `GET /forum/sections` | — | `200` с массивом `ForumSection` | публичный |
| Темы форума | `GET /forum/topics` | `section_id` в query | `200` с массивом `ForumTopic` | публичный |

## Обратная связь и подтверждения

В приложенном снимке Issue #13 есть только комментарий о назначении задачи и
автоматическое сообщение бота; технических замечаний или подтверждений от
согласующих ролей там нет. Поэтому ни одно решение не отмечено как
утверждённое.

Перед изменением публичного контракта нужны следующие явные подтверждения:

| Роль | Что подтвердить |
| --- | --- |
| Backend | Валидацию входных данных, реалистичность статусов и формат ошибок |
| Frontend | Точные поля форм регистрации, профиля и объявления; обработку `Error` |
| БД | UUID, обязательность и связи `User`, `University`, `Ad` и сущностей форума |
| QA | Сценарии успешных и ошибочных ответов, включая `401` и `400` |

## Открытые вопросы — не включены в контракт

Ни один из пунктов ниже не добавлен в `openapi.yaml`, чтобы не выдать
предположение за согласованное API:

1. Методы и статусы для редактирования и закрытия объявления из MVP.
2. Нужны ли пагинация, сортировка и формат списка для объявлений и тем.
3. Справочник категорий объявлений и допустимые значения `category_id`.
4. Создание тем, ответы на них и правила доступа к разделам форума.
5. Границы длины, допустимые форматы и способ изменения полей профиля.
6. Единый набор машинных значений `Error.code`, а также различие между
   ошибками валидации, конфликтом и отсутствием ресурса.
7. Время жизни токена, обновление токена и поведение при выходе из системы.

После письменного согласования каждый пункт должен быть внесён отдельным
изменением в OpenAPI с проверкой совместимости frontend, backend, БД и QA.

## Самостоятельная проверка

Из корня репозитория выполнить:

```powershell
npx --yes @redocly/cli@latest lint docs/api/openapi.yaml
```

Команда загружает валидатор только во временный кэш npm и не меняет
`package.json` или lock-файлы репозитория. Ожидаемый результат — отсутствие
ошибок OpenAPI. Стандартная конфигурация Redocly может выдать рекомендации о
лицензии, `operationId` и дополнительных 4xx-ответах; они не являются
ошибками схемы и оставлены на согласование, потому что затрагивают публичный
контракт. Для визуальной проверки можно открыть тот же файл в Swagger Editor.
