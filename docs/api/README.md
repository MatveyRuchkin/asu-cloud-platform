# Единый API-контракт

Файл `openapi.yaml` — проект контракта. **Он ещё не утверждён**. Перед тем как писать отдельные модули, аналитик, backend, frontend, БД и QA должны согласовать поля, методы, коды ответов, ошибки и права доступа.

Правила: REST/JSON, `/api/v1`, UUID в строке, `snake_case` в JSON, `null` обозначает отсутствие цены или ссылки, даты в ISO 8601 UTC. Не отправляем XML. JSON берём из форм на frontend и передаём backend в точно таком же виде.

## Процесс изменения контракта
1. Создать или обновить Issue с причиной изменения.
2. Исправить openapi.yaml и примеры, отметить ломающее изменение.
3. Получить согласование API-ответственного, backend и frontend, при изменении структуры — БД.
4. Запустить проверку OpenAPI / написать сценарий интеграции.
5. После merge реализация обеих сторон должна соответствовать новой версии.
