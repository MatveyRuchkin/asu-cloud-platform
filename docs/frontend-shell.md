# Каркас frontend: маршруты, навигация и вызов API

**Issue:** #8 (FE-01) · **Исполнитель:** Хапков Алексей (руководитель Frontend)
**Связано:** [архитектурные решения](architecture/decisions.md) · [структура проекта](architecture/structure.md) · [контракт API](api/openapi.yaml) · [frontend/README.md](../frontend/README.md)

Документ фиксирует, **как устроен общий каркас приложения** и **где участникам добавлять свои
экраны и компоненты**, чтобы не переделывать чужие файлы. Каркас создан в Issue #5 (ARCH-01),
FE-01 дополняет его общей навигацией и правилами ниже.

## 1. Что уже есть в каркасе

| Путь | Имя (`name`) | Заголовок | Владелец экрана |
| --- | --- | --- | --- |
| `/` | — | редирект на `/ads` | FE-01 |
| `/login` | `login` | Вход и регистрация | FE-02 (Юмина) |

**Как добавить маршрут:**

1. Создать страницу в `src/views/` (файл `PascalCase.vue`).
2. Добавить маршрут в `src/router/index.ts` с `name` и `meta.title`.
3. Если раздел должен быть в меню — добавить ссылку в `links` внутри `AppNavigation.vue`.
4. Если маршрут нужен срочно, а FE-01 недоступен — сообщить лиду в Issue, а не переписывать оболочку.

## 4. Навигация

`AppNavigation.vue` — единственный компонент навигации. Он:

- содержит список разделов в одном месте (`links`) и подсвечивает активный раздел;
- на экране ≤ 600 px сворачивается в кнопку-«бургер»; меню закрывается после перехода и по `Escape`;
- использует `aria-expanded`, `aria-controls` и `aria-label`, поэтому доступен с клавиатуры;
- не хранит состояние приложения: это делают страницы и Pinia-хранилища.

Страницы не дублируют меню и не добавляют свои ссылки в обход `links`.

## 5. Единый способ вызывать API

Любой запрос идёт через `apiRequest` из `src/api/http.ts`. Прямой `fetch` в компонентах запрещён:
иначе ошибки и заголовки будут обрабатываться по-разному в каждом экране.

```ts
import { ApiError, apiRequest } from '@/api/http'
import type { ForumSection } from '@/api/types'

const sections = await apiRequest<ForumSection[]>('/forum/sections')
```

Правила:

- адрес API берётся из `VITE_API_BASE_URL` (пример — `frontend/.env.example`);
- ошибка сервера приходит как `{code, message, details}` и превращается в `ApiError`;
  пользователю показываем `message`, по `code`/`status` выбираем поведение (`401` → экран входа);
- типы запросов и ответов лежат в `src/api/types.ts` и повторяют `openapi.yaml`;
- ответ `204` возвращает `undefined`, пустой список — `[]`;
- токен передаётся параметром `token` и подставляется в `Authorization: Bearer`.

**Состояния экрана.** У каждой страницы, которая грузит данные, должно быть три состояния:
загрузка, пустой ответ и ошибка. Пример обработки ошибки:

```ts
try {
  data.value = await apiRequest<ForumSection[]>('/forum/sections')
} catch (error) {
  message.value = error instanceof ApiError ? error.message : 'Не удалось загрузить данные'
}
```

## 6. Куда добавлять компоненты

| Каталог | Что кладём | Владелец |
| --- | --- | --- |
| `src/views` | страницы экранов | FE-02…FE-04 |
| `src/components` | переиспользуемые элементы и навигация | FE-01 |
| `src/router` | маршруты | FE-01 |
| `src/api` | запросы и типы | FE-01 + API-01 |
| `src/stores` | состояние Pinia | FE-01 |
| `src/styles` | переменные и общие стили | FE-01 + UI-01 |

Простое правило: **свою страницу — в `src/views`, общий элемент — в `src/components`**.
Файлы компонентов — `PascalCase.vue`, папки — `kebab-case`. Общие стили — только через
переменные из `styles/main.css` (`--color-accent`, `--space`, `--radius`), а не «магические» цвета.
Главная область страницы (`<main>`) одна и находится в `App.vue`: страница использует `<section>`
или `<div>`, иначе в разметке появляются две главные области.

## 7. Адаптивность

- Базовая вёрстка — «мобильная сначала»: контент помещается в одну колонку.
- Контрольная точка каркаса — **600 px**; на ней меню уходит в «бургер», а отступы уменьшаются.
- Горизонтальной прокрутки быть не должно ни на 320 px, ни на 1440 px.
- Максимальная ширина контента — 960 px (`.app` в `main.css`), страницы не растягиваются на весь монитор.
- Ширины и отступы задаются в `rem`/`px` через переменные, без фиксированных `width: 1200px`.

## 8. Проверки перед Pull Request

Из каталога `frontend/`:

```bash
npm install          # один раз
npm run type-check   # типы TypeScript и Vue
npm run lint         # ESLint
npm run format:check # Prettier
npm run build        # production-сборка
npm run dev          # ручная проверка: 320 px и 1440 px, переходы по всем четырём разделам
```

Результат команд вставляется в описание PR. Если проверка не запускалась — так и пишем, с причиной.
