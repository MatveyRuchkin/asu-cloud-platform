# Архитектура — предложенный стандарт

**Статус: черновик для утверждения технической командой.** До утверждения не следует независимо реализовывать несовместимые модули.

- Тип: модульный монолит, единый серверный API.
- Frontend: Vue 3 + TypeScript (предложение).
- Backend: Python + FastAPI (предложение).
- БД: PostgreSQL (предложение), миграции через Alembic.
- Локальный запуск: Docker Compose (предложение).
- API: REST, JSON по UTF-8, единая схема OpenAPI в `docs/api/openapi.yaml`.
- API префикс: `/api/v1`. В JSON поля в `snake_case`, идентификаторы UUID в строках, даты — ISO 8601 UTC; суммы — `price_rub` в целых рублях или `null`.

## Согласование перед изменениями
1. Любое изменение публичного API — Issue + обновление OpenAPI + согласование аналитика, backend, frontend и QA.
2. Изменение таблиц и миграций — ревью DB и Backend Lead; не менять ранее принятые миграции без отдельного решения.
3. Изменение библиотек, архитектуры и CI — ревью Tech Lead.
4. По умолчанию данные между модулями должны иметь одинаковые названия и типы от формы до обработчика и обратно.
5. Код не хранит реальные ключи, токены или персональные данные. Примеры данных вымышленные.

## Основные каталоги
`frontend/`, `backend/`, `tests/`, `data/demo/`, `docs/`, `site/`. Это целевая структура; новые каталоги появляются по мере выполнения Issues.
