# OpenCode: установка, бесплатные модели и выполнение своей задачи (для новичков)

**OpenCode — открытая и бесплатная программа, помогающая разбираться в проекте и менять файлы с помощью ИИ.** Однако **используемая через неё языковая модель может быть платной**. Само наличие OpenCode **не даёт автоматически безлимитный доступ к любым моделям**. Пользоваться Codex или покупать ChatGPT Plus ради нашего проекта **не обязательно**.

Эта инструкция написана прежде всего для студентов на **Windows**, но есть варианты для macOS и Linux.

**Официальные источники:**
- [Скачать OpenCode](https://opencode.ai/download).
- [Официальное руководство](https://docs.opencode.ai/docs/).
- [Как подключаются модели](https://docs.opencode.ai/docs/providers/).
- [Модели OpenCode Zen и их тарифы](https://docs.opencode.ai/docs/zen/).
- [Установка на Windows через WSL](https://docs.opencode.ai/docs/windows-wsl/).

## 1. Что заранее должно быть готово

Прежде чем устанавливать OpenCode, выполните [основную инструкцию](START_HERE.md) до **шага 8**:
1. Зарегистрируйтесь на GitHub.
2. Откройте личную GitHub Issue и напишите `беру`.
3. Сделайте Fork репозитория **MatveyRuchkin/asu-cloud-platform**.
4. Скачайте свой Fork на компьютер через GitHub Desktop.
5. Создайте отдельную ветку `feature/НОМЕР` от `dev`.

**Папка проекта уже должна быть на компьютере.** Не просите OpenCode создать новый `asu-cloud-platform` с нуля.

## 2. Самый понятный вариант — OpenCode Desktop (Windows)

1. Откройте браузер и официальный адрес **https://opencode.ai/download**.
2. Найдите раздел **OpenCode Desktop**.
3. Выберите загрузку **Windows (x64)**, если ваш компьютер с 64-разрядной Windows.
4. Скачайте установочный файл; если браузер предупреждает об опасности, проверьте, что вы на официальном домене и загрузка действительно от проекта OpenCode. Не отключайте защиту Windows ради случайного файла.
5. Запустите скачанный установщик; следуйте шагам на экране. Названия кнопок могут отличаться.
6. Запустите **OpenCode Desktop** через меню Пуск.
7. На начальном экране найдите открытие локального проекта/папки (**Open Folder / Open Project** или аналогичный пункт).
8. Выберите папку **вашего клонированного Fork**, например `C:\Users\ВАШ_ЛОГИН_WINDOWS\Documents\GitHub\asu-cloud-platform`.
9. Убедитесь, что программа видит `AGENTS.md`, `docs/`, `site/` и другие файлы репозитория.

**Не выбирайте** просто `Documents`, папку «Загрузки» или пустой каталог. OpenCode должен работать в папке проекта.

## 3. Если Desktop не работает — терминальный вариант

### Windows: установить через Node.js и npm

Это **альтернатива**, а не обязательная часть инструкции. Если Desktop работает, терминал можно не использовать.

1. Откройте **https://nodejs.org/**.
2. Скачайте рекомендуемую **LTS-версию Node.js** для Windows и установите её. Вместе с Node.js устанавливается программа `npm`.
3. Закройте и заново откройте Windows PowerShell (Пуск → в поиске написать «PowerShell»).
4. Проверьте командой:

```powershell
node --version
npm --version
```

5. Установите стабильную версию OpenCode способом из официальной документации:

```powershell
npm install -g opencode-ai
```

6. Убедитесь, что программа установилась:

```powershell
opencode --version
```

7. В PowerShell перейдите в папку **вашего клонированного репозитория**. Например (замените имя Windows-пользователя):

```powershell
cd "$HOME\Documents\GitHub\asu-cloud-platform"
opencode
```

Если папка лежит в другом месте, откройте её в Проводнике, скопируйте полный путь из адресной строки и используйте его в команде `cd "ВАШ_ПУТЬ"`.

**Важно:** официальный сайт может предлагать новую ветку OpenCode 2.0 с другими названием npm-пакета и командой запуска. Это отдельная, меняющаяся версия. **Не смешивайте** команды установки `opencode-ai` и `@opencode/cli` наугад: используйте один путь из актуальной официальной инструкции.

### macOS / Linux

Можно скачать Desktop с https://opencode.ai/download (поддерживаемые версии macOS/Linux) либо использовать инструкции для терминала:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Скрипты из интернета запускайте **только после проверки официального адреса** и если понимаете, что делает команда. Если сомневаетесь, скачайте Desktop. На Windows разработчики OpenCode отдельно рекомендуют WSL для опытных пользователей, но новичкам не нужно ставить WSL, если работает Desktop.

## 4. Самый важный вопрос: как пользоваться бесплатно

OpenCode **не является моделью**: он связывает файлы проекта с выбранной моделью ИИ.

Варианты:
- **Доступная бесплатная модель OpenCode** (если есть в текущем выборе моделей). Названия и ограничения могут меняться.
- **Бесплатный тариф другого провайдера**, если он есть и подходит; иногда требуется регистрация или API-ключ, но это не обязательно подписка.
- **Локальная модель** на собственном компьютере — сложнее, подходит для достаточно мощных ПК; не рекомендуем как первый шаг для большинства студентов.
- Платные провайдеры — **не обязательны**, не подключайте их без собственного решения.

**Как проверить, действительно ли модель бесплатна:**
1. В OpenCode откройте список моделей. В терминальной версии введите **`/models`**, в Desktop найдите переключатель модели.
2. Посмотрите на название/метку **Free** и условия выбранного провайдера.
3. Если приложение просит добавить API-ключ, подписку, деньги или карту — **не считайте это бесплатным вариантом**. Отмените шаг и выберите другой вариант либо спросите наставника.
4. Сверьте условия на официальной странице провайдера. Бесплатные модели могут иметь лимиты запросов и могут исчезать.

**OpenCode Zen** — дополнительный сервис предоставления моделей. У него могут быть бесплатные модели, но в официальной настройке Zen может требоваться аккаунт и платёжные данные. **Не обещаем, что Zen всегда доступен без карты или без оплаты.** Если вас просят оплатить, это не обязательное условие для участия в нашем проекте.

**Никогда не отправляйте API-ключи в GitHub Issues, Pull Requests или в публичный чат.** Не записывайте их в код и документы репозитория.

## 5. Как дать OpenCode первое задание

1. Убедитесь, что GitHub Desktop показывает **`feature/НОМЕР`**, а не `main`.
2. Откройте OpenCode в папке проекта.
3. В интерфейсе выберите доступную модель.
4. Если есть **режим Plan (план)**, сначала используйте его. В терминальной версии текущая документация описывает переключение режима клавишей **Tab**; в Desktop интерфейс может отличаться.
5. Скопируйте следующий текст, подставив **реальную** ссылку на свою Issue и её номер:

> Я начинающий участник студенческого командного проекта https://github.com/MatveyRuchkin/asu-cloud-platform. Открыл локальную папку своего Fork, рабочая ветка — feature/МОЙ_НОМЕР. Моя задача: https://github.com/MatveyRuchkin/asu-cloud-platform/issues/МОЙ_НОМЕР. Сначала прочитай AGENTS.md, CONTRIBUTING.md, docs/requirements.md и персональный файл из docs/tasks/. Если задача затрагивает API, прочитай docs/api/openapi.yaml. Сначала объясни простыми словами, что требуется, какие файлы надо изменить и как проверить результат. НЕ ИЗМЕНЯЙ файлы, пока я не подтвержу план. Не создавай проект заново, не меняй чужие модули, API, зависимости, базу данных или архитектуру без согласования. Не выполняй git push/merge без моего разрешения. Затем помоги выполнить один маленький шаг за раз.

6. Прочитайте план и убедитесь, что он соответствует вашей Issue. Если непонятно — задайте вопрос на русском простыми словами.
7. Когда будете готовы, разрешите выполнение **только своей задачи**. Если OpenCode запрашивает доступ к редактированию/командам, сначала посмотрите, что именно будет изменено.
8. После выполнения откройте **GitHub Desktop → Changes**. Сравните затронутые файлы с ожидаемыми.
9. Запустите доступные проверки. Попросите OpenCode объяснить, **как вручную проверить результат**, и выполните эту проверку.
10. Когда убедились, что всё хорошо, сохраняйте работу через Commit, Push и PR по [основной инструкции, шаги 11–12](START_HERE.md).

## 6. Важно про файл AGENTS.md и команду /init

В нашем репозитории **уже есть общий `AGENTS.md`** со стандартами команды. OpenCode может предложить выполнить `/init`, чтобы автоматически создать этот файл.

**НЕ запускайте `/init` с перезаписью AGENTS.md без согласования с техническим руководителем.** Мы не хотим, чтобы нейросеть случайно заменила правила всего проекта правилами для одного человека.

## 7. Как добиться более качественного результата бесплатно

Не тратьте бесплатные запросы на просьбу «напиши мне всю платформу». Работайте мелкими шагами:

1. «Объясни мою задачу простыми словами и составь план».
2. «Проверь, какие файлы уже есть, не придумывай новые библиотеки».
3. «Покажи пример одной маленькой части и объясни, зачем она нужна».
4. «Согласуй формат JSON с docs/api/openapi.yaml».
5. «Напиши понятную проверку и объясни, как её запустить».
6. «Перечисли изменённые файлы и проверь, не тронул ли чужой код».

Если бесплатная модель плохо справляется, попросите наставника разделить задачу или уточнить требования. Не нужно оплачивать подписку ради первой задачи.

## 8. Возможные проблемы

**«OpenCode не видит файлы репозитория»** — откройте именно папку `asu-cloud-platform` из GitHub Desktop (Repository → Show in Explorer/Finder), а не пустую папку.

**«opencode не является внутренней или внешней командой»** — попробуйте перезапустить PowerShell и выполнить `npm install -g opencode-ai` ещё раз; если проблема не решается, используйте Desktop.

**«npm не найден»** — Node.js не установлен или PowerShell был открыт до установки. Установите LTS Node.js и откройте новое окно.

**«OpenCode просит ключ / карту»** — это конкретный провайдер/модель. Не вводите деньги/карту без понимания цены; выберите доступную бесплатную альтернативу, если есть.

**«ИИ хочет переписать весь проект»** — остановите его, скажите «меняй только файлы Issue №...» и попросите показать план. Не принимайте изменения вслепую.

**«После работы появились лишние файлы»** — проверьте GitHub Desktop → Changes, не добавляйте к коммиту мусор и секреты.

**«Что делать с кодом, который написал OpenCode?»** — сохранять его как реальные файлы в клонированной папке, а не копировать только переписку. Потом GitHub Desktop → Commit → Push → PR в `dev`.

**«Я дизайнер / пишу презентацию, зачем OpenCode?»** — он **не обязателен**. Можно использовать Figma, текстовый редактор или любой доступный ИИ для своих документов и сдавать результаты через GitHub.
