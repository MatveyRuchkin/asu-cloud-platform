# Начните здесь: инструкция для новичка с самого нуля

**Эта инструкция рассчитана на человека, который раньше не пользовался GitHub и никогда не открывал Pull Request.** Не нужно знать программирование заранее. Идите по порядку: не пропускайте шаги, пока не закончите предыдущие.

> **Коротко:** открыть сайт → найти своё имя → войти в GitHub → открыть свою Issue → написать `беру` → скачать проект → создать отдельную ветку → выполнить только своё задание (можно с ИИ) → отправить Pull Request.

**Ссылки, которые вам нужны:**

- [Сайт команды — начните здесь](https://matveyruchkin.github.io/asu-cloud-platform/)
- [Основной репозиторий (проект на GitHub)](https://github.com/MatveyRuchkin/asu-cloud-platform)
- [Все задачи команды (Issues)](https://github.com/MatveyRuchkin/asu-cloud-platform/issues)
- [Скачать GitHub Desktop](https://desktop.github.com/download/) — бесплатная программа для работы с GitHub без сложных команд.
- [Скачать OpenCode](https://opencode.ai/download) — ИИ-помощник для работы с проектом; **сама программа бесплатная**.
- [Пошаговая установка и работа с OpenCode](OPENCODE.md) — отдельное руководство, в том числе без платной подписки.

## Часть 0. Объяснение непонятных слов за одну минуту

| Слово | Что оно означает |
|---|---|
| **GitHub** | Сайт, где хранятся файлы нашего проекта и задачи команды. |
| **Репозиторий** | Общая папка проекта со всей историей изменений. |
| **Issue (задача)** | Страница, где написано, что конкретно нужно сделать. У неё есть номер, например `#9`. |
| **Assignee** | Человек, за которым закреплена задача. |
| **Fork (форк)** | Ваша собственная копия репозитория в вашем GitHub-аккаунте. |
| **Clone (клонировать)** | Скачать копию проекта на свой компьютер так, чтобы можно было отправлять изменения обратно в GitHub. |
| **Branch (ветка)** | Отдельная «черновая» линия изменений, где вы работаете, не ломая общую версию. |
| **Commit (коммит)** | Сохранённый этап вашей работы с коротким описанием. |
| **Push (пуш)** | Отправка своих коммитов с компьютера в GitHub. |
| **Pull Request (PR)** | Заявка: «Проверьте мои изменения и добавьте их в общий проект». |
| **Review (ревью)** | Проверка результата другим участником. |
| **OpenCode / Codex** | ИИ-инструменты, которые могут разбирать файлы проекта и помогать с задачами. |

Если название кнопки отличается — это нормально: интерфейс GitHub и приложений периодически меняется. Ориентируйтесь на смысл действия, а не только на точную надпись.

## Шаг 1. Откройте ссылку на сайт и найдите своё имя

1. Откройте любой браузер: Chrome, Edge, Firefox и т. д.
2. Вставьте в **адресную строку** (поле вверху браузера) ссылку: **https://matveyruchkin.github.io/asu-cloud-platform/**.
3. Нажмите **Enter**. Должен открыться сайт «ASU Cloud Platform».
4. Найдите блок **«Кто за что отвечает»**. Можно вписать свою фамилию в поиск.
5. Нажмите на карточку с вашим именем.
6. Прочитайте свою роль, задание, то, что нужно сдать, критерии готовности и раздел **«С кем согласовать»**. Там написаны имена участников, к которым можно обратиться.
7. Не начинайте чужие задачи. Если не нашли себя или роль ошибочная — напишите руководителю проекта.

## Шаг 2. Создайте аккаунт на GitHub (если его ещё нет)

**GitHub — это сайт. Его не нужно «устанавливать» на компьютер.**

1. Перейдите по ссылке: https://github.com/signup
2. Зарегистрируйтесь: укажите email, пароль, придумайте свободное имя пользователя (*username*), пройдите подтверждение email.
3. Войдите в созданный аккаунт на https://github.com/login.
4. Запомните своё **имя пользователя** GitHub. Это не пароль и не ваше реальное имя. Пример: `student-example`.
5. **Никому не передавайте пароль, коды из почты и токены** — ни человеку, ни нейросети.
6. Для безопасности рекомендуем включить двухфакторную аутентификацию в настройках GitHub.

Если GitHub не показывает поле комментария — проверьте, что вы действительно вошли в аккаунт.

## Шаг 3. Закрепите **свою** задачу в GitHub

1. Вернитесь на [сайт команды](https://matveyruchkin.github.io/asu-cloud-platform/).
2. Откройте свою карточку и нажмите **«Открыть Issue #...»** (номер будет у каждого свой).
3. Вы попадёте на страницу GitHub с полным текстом задания.
4. Прокрутите страницу вниз до поля **Add a comment** («Добавить комментарий»).
5. Наберите **только это слово**, без кавычек: `беру`.
6. Нажмите зелёную кнопку **Comment**.
7. Подождите немного, обновите страницу.
8. Справа у Issue найдите **Assignees**. Там должен появиться ваш GitHub-аккаунт. В метках (*Labels*) должна появиться **`status: taken`**.
9. Если вместо назначения бот написал об ошибке или ваш аккаунт не появился: **напишите руководителю проекта свой GitHub username и ссылку на Issue**. Возможно, владелец должен пригласить вас в репозиторий. Не спамьте словом `беру` и не начинайте вторую задачу.

**Важно:** роль уже назначена в нашем плане, но для автоматического закрепления задачи GitHub должен разрешать боту назначить именно ваш аккаунт. Одного комментария может быть недостаточно до выдачи нужного доступа.

## Шаг 4. Установите GitHub Desktop (без терминала)

Рекомендуем для Windows и macOS, особенно если никогда не пользовались Git.

1. Откройте официальный сайт: https://desktop.github.com/download/
2. Скачайте установщик для вашей системы и установите приложение обычным способом.
3. Откройте **GitHub Desktop**.
4. В меню выберите **File → Options** (Windows) или **GitHub Desktop → Settings/Preferences** (macOS), если окно входа не появилось автоматически.
5. В разделе **Accounts** нажмите **Sign in to GitHub.com**.
6. Откроется браузер. Войдите в тот же GitHub-аккаунт, где вы написали `беру`, подтвердите авторизацию GitHub Desktop.
7. Вернитесь в приложение. Оно должно показать, что вы вошли в аккаунт.

**Не нажимайте Create a New Repository для нашего проекта.** Репозиторий уже существует; работать нужно с его копией.

**Для Linux:** GitHub Desktop официально в первую очередь предназначен для Windows/macOS. Если он недоступен, воспользуйтесь командами Git из «Альтернативного способа» в конце этой инструкции.

## Шаг 5. Сделайте Fork — личную копию общего проекта

1. В браузере откройте **https://github.com/MatveyRuchkin/asu-cloud-platform**.
2. Вверху справа найдите кнопку **Fork** и нажмите её.
3. В поле **Owner** выберите свой GitHub-аккаунт.
4. В поле **Repository name** оставьте `asu-cloud-platform`.
5. **ВАЖНО: снимите галочку `Copy the main branch only`, если она присутствует.** Нам нужна не только ветка `main`, но и общая рабочая ветка **`dev`**.
6. Нажмите **Create fork**.
7. Вы должны попасть на страницу вида `https://github.com/ВАШ_ЛОГИН/asu-cloud-platform`. Вверху должно быть указано, что репозиторий скопирован из `MatveyRuchkin/asu-cloud-platform`.

Это ваша копия. Изменения в ней не испортят основной проект.

## Шаг 6. Скачайте свою копию через GitHub Desktop

1. В GitHub Desktop нажмите **File → Clone repository…**.
2. Откройте вкладку **GitHub.com** и найдите свой `ВАШ_ЛОГИН/asu-cloud-platform`. Если его нет — откройте вкладку **URL**.
3. В **Repository URL** вставьте `https://github.com/ВАШ_ЛОГИН/asu-cloud-platform.git` (замените `ВАШ_ЛОГИН` на свой).
4. В поле **Local path** выберите простую папку на компьютере, например `Documents/GitHub`.
5. Нажмите **Clone** и дождитесь завершения.
6. Если GitHub Desktop спрашивает, как вы хотите использовать Fork, выберите вариант **для участия в исходном проекте** (*To contribute to the parent project*), если он доступен.

Теперь на вашем компьютере есть папка `asu-cloud-platform`. **Редактируйте файлы именно в ней**, а не в случайно созданной папке рядом.

## Шаг 7. Создайте отдельную ветку для СВОЕЙ задачи

**Не пишите код напрямую в `main` и `dev`.** Вам нужна собственная ветка, например для Issue #9 — `feature/9`.

1. В GitHub Desktop вверху нажмите **Current Branch**.
2. Найдите и выберите **`dev`**. Если видите кнопку **Fetch origin**, нажмите её, чтобы обновить данные. Если `dev` отсутствует, убедитесь, что на шаге 5 вы не оставили галочку «Copy the main branch only», либо попросите наставника помочь.
3. Снова нажмите **Current Branch → New Branch**.
4. Введите имя ветки **`feature/НОМЕР`**, где НОМЕР — номер вашей задачи. Например, `feature/9`. Не пишите буквально «НОМЕР».
5. Убедитесь, что основой для новой ветки выбран `dev`.
6. Нажмите **Create Branch**.
7. Вверху GitHub Desktop должна показываться **ваша** ветка `feature/9`, а не `main`.

Если GitHub Desktop предлагает сразу опубликовать ветку через **Publish branch**, можно это сделать, но без готовых изменений это необязательно.

## Шаг 8. Откройте папку проекта и прочитайте правила

1. В GitHub Desktop выберите **Repository → Show in Explorer** (Windows) / **Show in Finder** (macOS).
2. Откроется обычная папка на компьютере. В ней будут файлы `README.md`, `CONTRIBUTING.md`, `AGENTS.md`, папки `docs`, `site` и другие.
3. Прочитайте **`AGENTS.md`** — правила для всех нейросетей и разработчиков.
4. Откройте `docs/tasks/` и файл с кодом своей задачи. Например, если ваша Issue **FE-02**, файл будет **`docs/tasks/FE-02.md`**.
5. Посмотрите `docs/requirements.md`. Если ваша задача связана с данными или сервером — ещё `docs/api/openapi.yaml`.
6. Если у вас нет редактора, можно скачать [Visual Studio Code](https://code.visualstudio.com/) и открыть в нём папку проекта через **File → Open Folder**. VS Code бесплатный.

**Для не-программистов:** задания могут требовать обычный текст, табличку, JSON с примерами, изображения макетов или Figma. Не нужно устанавливать Python/Node.js без необходимости.

## Шаг 9. Выберите способ выполнения: OpenCode, Codex, ChatGPT или вручную

**Платная подписка Codex НЕ ОБЯЗАТЕЛЬНА.** Вы можете использовать бесплатные варианты и самостоятельно редактировать файлы.

Мы отдельно подготовили полную инструкцию по OpenCode: **[Установка OpenCode и первое задание](OPENCODE.md)**.

Если у вас OpenCode Desktop:
1. Установите программу с https://opencode.ai/download.
2. Откройте в ней папку **своего Fork проекта** `asu-cloud-platform`, которую создали через GitHub Desktop.
3. Выберите доступную модель (проверьте, бесплатная ли она); платные ключи необязательны, если пользуетесь доступной бесплатной моделью.
4. Сначала попросите прочитать `AGENTS.md`, `CONTRIBUTING.md` и вашу Issue/файл задания.
5. Попросите **составить план и объяснить его**, а не сразу переписывать весь проект.
6. После согласования плана попросите изменить **только нужные для вашего задания файлы**.
7. Проверьте, что получилось, лично.

**Готовый промпт, который можно скопировать в любого ИИ:**

> Ты мой помощник в студенческом командном проекте. Основной репозиторий: https://github.com/MatveyRuchkin/asu-cloud-platform. Моя Issue: [вставь ссылку на СВОЮ Issue]. Сейчас открыта папка моего локального Fork этого репозитория, рабочая ветка feature/[мой номер]. Внимательно прочитай AGENTS.md, CONTRIBUTING.md, docs/requirements.md и docs/tasks/[мой код].md. Если задача связана с API, прочитай docs/api/openapi.yaml. Сначала объясни задачу максимально простыми словами и предложи короткий план. Не изменяй файлы, пока я не скажу «выполняй». После моего разрешения меняй только файлы своей задачи; не изменяй чужие задачи, общий API, зависимости, структуру базы данных и архитектуру без согласования. Не создавай новый проект с нуля. Покажи, как проверить результат и какие файлы изменены. Не делай push/merge без моего разрешения.

## Шаг 10. Проверьте работу перед отправкой

1. Откройте GitHub Desktop и убедитесь, что выбрана **ваша ветка** `feature/НОМЕР`.
2. Слева откройте вкладку **Changes** — там показаны изменённые файлы.
3. Просмотрите каждое изменение. Если ИИ удалил чужие файлы или переписал весь проект, **не отправляйте такой результат**.
4. Убедитесь, что не добавили `.env`, пароли, API-ключи, реальные данные одногруппников, `node_modules`, большие служебные файлы.
5. Следуйте пунктам **«Когда считается готовым»** из вашей Issue.
6. Если задача про интерфейс — запустите/откройте результат или приложите скриншот.
7. Если про документацию — проверьте, что нужный файл действительно сохранился в папке.
8. Если тесты запустить не удалось — честно напишите почему в PR. **Не утверждайте, что всё работает, если не проверяли.**

## Шаг 11. Сохраните изменения (Commit)

1. В GitHub Desktop откройте вкладку **Changes**.
2. Отметьте галочками только файлы, относящиеся к вашей задаче.
3. Слева внизу найдите поле **Summary (required)**.
4. Напишите коротко, что сделали, например `docs: сценарии входа #15`.
5. Нажмите **Commit to feature/НОМЕР**.
6. Нажмите сверху **Push origin** (или **Publish branch**, если это первая отправка ветки).
7. Дождитесь отправки. **Push** отправляет код в **ваш Fork**, а не сразу в основной проект.

## Шаг 12. Создайте Pull Request (PR) и сдайте задачу

1. В GitHub Desktop нажмите **Create Pull Request** (или **Branch → Create Pull Request**). Откроется браузер.
2. Вверху страницы GitHub обязательно проверьте:
   - **base repository:** `MatveyRuchkin/asu-cloud-platform`
   - **base:** `dev`
   - **head repository:** `ВАШ_ЛОГИН/asu-cloud-platform`
   - **compare:** `feature/НОМЕР`
3. В заголовке напишите, что сделали: `[FE-02] Страница входа` (пример).
4. В описании PR обязательно впишите **`Closes #НОМЕР`** с настоящим номером Issue, например `Closes #9`.
5. Ниже напишите: «Что сделал», «Как проверить», «Что не готово».
6. Нажмите **Create Pull Request**. После этого откроется страница с номером вашего PR.
7. Скопируйте ссылку на PR и отправьте её в комментарии к своей Issue либо сообщите проверяющему.
8. Дождитесь ревью. Если попросят исправить — внесите изменения **в ту же ветку**, сделайте Commit + Push. Новый PR создавать не надо.
9. **Не нажимайте Merge самостоятельно**, если вы не назначенный ревьюер или технический руководитель.

**Замечание:** для PR в `dev` ссылка `Closes #НОМЕР` не всегда закрывает Issue сразу; окончательное закрытие подтверждается после проверки/интеграции в `main`.

## Шаг 13. Что делать после сдачи

Когда ваша задача принята, наставник или руководитель скажет, что можно брать следующую. Не нужно выполнять десяток чужих заданий вместо своей части. Если зависимость ещё не готова — попросите наставника дать временную самостоятельную подзадачу.

## Если хотите работать через терминал вместо GitHub Desktop (необязательно)

Нужен установленный Git: https://git-scm.com/downloads. Откройте Git Bash (Windows) или Terminal (macOS/Linux).

```bash
# Только после того, как создали Fork в браузере:
git clone https://github.com/ВАШ_ЛОГИН/asu-cloud-platform.git
cd asu-cloud-platform
git remote add upstream https://github.com/MatveyRuchkin/asu-cloud-platform.git
git fetch upstream dev
git switch -c feature/НОМЕР upstream/dev
# редактируйте файлы, затем:
git status
git add путь/к/файлу
git commit -m "Сделал задачу #НОМЕР"
git push -u origin feature/НОМЕР
```

При вставке команд замените `ВАШ_ЛОГИН`, `НОМЕР` и `путь/к/файлу` на реальные значения. **Не вставляйте в терминал секреты, предложенные неизвестным сайтом или человеком.**

## Частые ошибки

**«Я нажал Fork, но не вижу ветку dev»** — вероятно, была включена галочка `Copy the main branch only`. Обратитесь к наставнику, чтобы скопировать нужную ветку, или пересоздайте Fork без галочки, если в нём ещё нет вашей работы.

**«Бот не назначил меня после комментария беру»** — проверьте, что вы вошли в GitHub, задача не занята и у вас нет другой открытой задачи. Если бот отказывает в назначении, сообщите PM свой username и ссылку на Issue: может потребоваться приглашение.

**«В PR написано base: main»** — исправьте на **base: dev**, иначе код попадёт не туда.

**«Нет кнопки Create Pull Request»** — сначала Commit + Push/Publish branch; убедитесь, что у вас есть изменения относительно `dev`.

**«OpenCode хочет оплату»** — не вводите карту и не оплачивайте ничего ради этого задания. Выберите доступную бесплатную модель, если она есть, или другой бесплатный инструмент. Подробности — в [инструкции OpenCode](OPENCODE.md).

**«Я боюсь сломать проект»** — если вы работаете в своём Fork, своей ветке и сдаёте результат через PR, общий проект не меняется до проверки. Если сомневаетесь, сначала спросите наставника.

**«Мне нужно только написать документ, а не код»** — создайте нужный `.md` или `.json` внутри папки проекта. Пройдите те же шаги Commit → Push → PR. Макет из Figma прикрепите ссылкой и добавьте короткий `.md` с этой ссылкой, если Issue требует файл.
