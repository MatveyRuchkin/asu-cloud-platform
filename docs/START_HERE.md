# Инструкция с нуля: GitHub, задание, OpenCode и сдача работы

> **Для кого:** для тех, кто вообще никогда не работал с GitHub, Git и программированием. Можно идти по пунктам подряд. Если что-то не получается — сообщите руководителю проекта; не нужно делать вид, что всё работает.
>
> **Главное:** у каждого из нас **своя задача**, но **один общий проект**. Не создаём новое приложение вместо общего и не отправляем код только в Telegram.

Найдите себя и посмотрите, кто отвечает за вашу группу. Спрашивайте сначала его; сложные технические вопросы лидер передаст Михаилу Сергеенко, организационные — Матвею Ручкину.

## 1. Зарегистрироваться на GitHub (если нет аккаунта)

1. Откройте https://github.com/signup .
2. Укажите **свою** электронную почту, придумайте пароль, выберите ник (username).
3. Если GitHub попросит подтвердить почту — откройте письмо и выполните подтверждение.
4. Откройте https://github.com/MatveyRuchkin/asu-cloud-platform . Если справа вверху виден ваш аватар — вы вошли.
5. Сообщите руководителю проекта **только GitHub-ник**, например `@example123`. Пароль и коды подтверждения никому не отправлять.

Если видите **404** или не можете комментировать задачу — убедитесь, что вошли в аккаунт, затем отправьте руководителю ссылку на свой профиль. Если вас пригласили в репозиторий, приглашение нужно принять.

## 2. Найти СВОЮ задачу на сайте

1. Перейдите на https://matveyruchkin.github.io/asu-cloud-platform/ .
2. Прокрутите до раздела **«Кто за что отвечает»**.
3. Введите свою фамилию в поле поиска; нажмите карточку с вашим именем.
4. Прочитайте **роль**, **первое задание**, **что сдать**, **как проверят** и **с кем согласовать**.
5. Нажмите **«Открыть Issue #…»**. Откроется страница GitHub именно с вашей задачей.

Если на сайте указаны неправильные обязанности — сначала напишите руководителю, **не берите чужую задачу**.

## 3. «Прикрепиться» к задаче словом «беру»

1. На странице вашей Issue прокрутите в самый низ.
2. Найдите поле **Add a comment** (или **Leave a comment**).
3. Напишите **ровно одно слово:** `беру` .
4. Нажмите **Comment**.
5. Подождите немного и обновите страницу. С правой стороны (или в боковом меню на телефоне) найдите **Assignees**: там должен появиться ваш GitHub-ник. Рядом должна быть метка **status: taken**.
6. Если бот написал, что не смог назначить вас, сообщите руководителю: вероятно, у аккаунта пока недостаточно прав. **Не публикуйте пароль.**

Это делает [Issue Claim Bot](https://github.com/MatveyRuchkin/asu-cloud-platform/blob/main/.github/workflows/claim.yml). Он проверяет, не занята ли задача. До закрытия текущей задачи вторую брать нельзя.

## 4. Установить необходимые программы

Ниже путь **для Windows**. Если у вас Mac/Linux — команды Git аналогичные, но установку смотрите на официальных сайтах.

### 4.1. Git — чтобы сохранять изменения и отправлять их в GitHub

1. Откройте https://git-scm.com/downloads .
2. Скачайте **Git for Windows**, установите. Если не знаете, что выбирать, оставляйте стандартные параметры.
3. Откройте **Пуск → PowerShell** или **Git Bash**.
4. Введите `git --version` и нажмите Enter. Если появилась версия Git — готово.
5. Один раз настройте имя для истории изменений (вместо примеров подставьте свои данные):

```bash
git config --global user.name "Ваше имя"
git config --global user.email "почта-которую-вы-используете-на-GitHub@example.com"
```

Ошибка `git is not recognized` означает, что Git не установлен или терминал надо перезапустить. Не продолжайте дальше, пока `git --version` не работает.

### 4.2. VS Code — чтобы удобно видеть файлы (необязательно, но советуем)

1. Откройте https://code.visualstudio.com/ .
2. Скачайте установщик для своей системы, установите.
3. Чтобы открыть папку проекта, запустите VS Code → **File → Open Folder…** → выберите папку `asu-cloud-platform` после скачивания.

### 4.3. GitHub Desktop — вариант без большого количества команд

Можно установить https://desktop.github.com/ . Приложение позволяет клонировать форк, создать ветку, посмотреть изменённые файлы, сделать Commit и Push с помощью кнопок. Использовать одновременно и Desktop, и терминал необязательно: выберите один способ.

## 5. Сделать копию проекта у себя и скачать на компьютер

> **Важно:** используйте именно Fork, а не кнопку **Create new repository**. Нам нужен один общий исходный проект.

1. Откройте https://github.com/MatveyRuchkin/asu-cloud-platform .
2. Справа сверху нажмите **Fork** → **Create a new fork**. Владелец — ваш аккаунт. Создайте форк.
3. В адресной строке браузера должна появиться ссылка вида `https://github.com/ВАШ_ЛОГИН/asu-cloud-platform`.
4. Откройте PowerShell или Git Bash, перейдите в удобную папку, например `cd Desktop` (если команда выдаёт ошибку, выберите другую существующую папку).
5. Скопируйте следующие команды, **заменив ВАШ_ЛОГИН на свой настоящий GitHub-ник**.

```bash
git clone https://github.com/ВАШ_ЛОГИН/asu-cloud-platform.git
cd asu-cloud-platform
git remote add upstream https://github.com/MatveyRuchkin/asu-cloud-platform.git
git fetch upstream
```

При первом скачивании GitHub может попросить войти через браузер — выполните авторизацию. **Не вводите пароль GitHub вместо токена в терминал**.

Проверьте командой `git remote -v`. Должны быть две ссылки: `origin` — ваша копия, `upstream` — общий проект.

Если `fatal: destination path ... already exists`, значит папка уже существует. Не создавайте вторую с тем же именем: откройте существующую и сначала уточните, были ли там ваши изменения.

## 6. Создать отдельную ветку под вашу задачу

В GitHub у каждой задачи есть номер, например #10. **Подставьте свой номер**, не копируйте номер из чужой инструкции.

В терминале внутри папки проекта:

```bash
git fetch upstream dev
git switch -c feature/НОМЕР upstream/dev
```

Для Issue #10 это будет `git switch -c feature/10 upstream/dev`.

Проверьте `git branch --show-current`: должна отображаться `feature/10` (или ваш номер). **Никогда не изменяйте напрямую общую `main` или `dev`.**

Если вы уже создавали эту ветку и видите `a branch named ... already exists`, используйте `git switch feature/НОМЕР` вместо её повторного создания.

## 7. OpenCode: бесплатный инструмент для помощи с кодом

**OpenCode — бесплатная программа с открытым исходным кодом**, которая может читать файлы проекта и помогать их менять. **Важно:** работа самой программы бесплатна, но используемая языковая модель может быть платной. Не выбирайте платную модель и не вводите банковскую карту, если не планируете расходы. Доступность бесплатных моделей и лимиты меняются — проверяйте стоимость у выбранного провайдера.

Официальные инструкции: https://opencode.ai/docs/ . OpenCode также существует как терминальное приложение и десктопное приложение.

### 7.1. Установить OpenCode через Windows + Node.js

1. Откройте https://nodejs.org/ и скачайте **LTS**-версию Node.js для Windows.
2. Установите Node.js со стандартными параметрами.
3. **Закройте и снова откройте PowerShell**.
4. Введите `node --version`, затем `npm --version`. Если обе команды возвращают версии — продолжайте.
5. В PowerShell выполните:

```powershell
npm install -g opencode-ai
```

6. Проверьте:

```powershell
opencode --version
```

7. Если PowerShell блокирует запуск `npm.ps1` политикой выполнения, не отключайте защиту наугад: откройте **Command Prompt (cmd)** и повторите команды там либо обратитесь к наставнику.
8. Если OpenCode пишет `command not found`, перезапустите терминал; при необходимости переустановите Node.js с PATH.

На Windows разработчики также рекомендуют **WSL** для лучшей совместимости, но для первой попытки можно начать с установки через npm. macOS/Linux: смотрите официальный установщик или Homebrew на https://opencode.ai/docs/ .

### 7.2. Как запустить OpenCode в нашей папке

1. Откройте терминал **внутри** папки `asu-cloud-platform`. Чтобы проверить, выполните `git status`: вы должны увидеть информацию о ветке.
2. Выполните команду:

```bash
opencode
```

3. Внутри OpenCode сначала выберите модель: `/models`.
4. **Если есть вариант с явно указанной нулевой ценой или бесплатной квотой**, выберите его после проверки условий. Не всякий вариант с надписью `Free` имеет безлимитный доступ.
5. Если нет доступных моделей, введите `/connect` и выберите поддерживаемого провайдера с бесплатным тарифом (если у вас есть такой аккаунт). Провайдер может потребовать API-ключ. Никогда не добавляйте API-ключи в файлы проекта, Issues или комментарии. Не сообщайте ключ нейросети.
6. Если бесплатного удалённого провайдера нет, OpenCode поддерживает **локальные модели** (на подходящем компьютере, через совместимый локальный сервер). Это требует отдельной настройки и достаточно мощного компьютера. Не обещаем, что на любом ноутбуке всё будет быстрым.

**Важно:** OpenCode Zen — не синоним бесплатной модели. У Zen могут быть платные запросы, поэтому не вводите платёжные данные ради учебной работы.

### 7.3. Что написать OpenCode первым сообщением

Скопируйте этот текст. **Замените номер на свою Issue**:

> Я участник проекта https://github.com/MatveyRuchkin/asu-cloud-platform, моя Issue №НОМЕР. Сначала прочитай README.md, AGENTS.md, CONTRIBUTING.md, docs/requirements.md, docs/architecture.md, docs/api/openapi.yaml и docs/tasks/МОЙ_КОД.md. Объясняй мне всё простым языком, как новичку. Сначала проверь, что я нахожусь в правильной ветке. Дай короткий план и покажи, какие файлы придётся изменить. Не переписывай проект целиком. Не меняй общие JSON-поля, API, БД или архитектуру без согласования с коллегами. Перед любым действием, которое удаляет файлы, отправляет код или устанавливает зависимости, объясни последствия. Выполняй задачу по одному небольшому шагу. В конце объясни, как я могу проверить результат, и подготовь краткое описание для Pull Request.

**Где взять МОЙ_КОД?** На сайте у карточки указан код вроде `FE-03`. Например, ваш файл будет `docs/tasks/FE-03.md`.

Полезные вопросы для помощника:
- «Объясни, что означает эта ошибка и как её исправить».
- «Что именно делает этот файл? Объясни без сложных терминов».
- «Какие тесты или проверки мне запустить до PR?».
- «Проверь, не поменял ли ты общие интерфейсы проекта».

OpenCode может предлагать выполнение команд и изменение файлов. **Внимательно читайте запросы на разрешение и не подтверждайте удаление важных данных или отправку секретов.**

### 7.4. Другие варианты без платной подписки

OpenCode — не единственный способ. Можно использовать бесплатные тарифы ChatGPT и других нейросетей для **объяснения задания, создания отдельных файлов и проверки кода**, копируя небольшие фрагменты вручную в VS Code. Codex и другие платные агенты **не обязательны**. У разных сервисов есть ограничения и лимиты.

## 8. Проверить изменения и отправить их в GitHub

1. Попросите OpenCode объяснить, что он изменил. Откройте файлы в VS Code.
2. В терминале внутри папки проекта выполните `git status` и `git diff`. Убедитесь, что нет чужих изменений или секретов.
3. Выполните способ проверки, который указан в вашей Issue: тест, открытие страницы, валидатор JSON или проверка документа.
4. Сохраните изменения:

```bash
git add .
git commit -m "feat: выполнить задачу #НОМЕР"
git push -u origin feature/НОМЕР
```

**ВНИМАНИЕ:** до `git add .` проверьте `git status` — иначе случайно можно отправить ненужные файлы. Если сомневаетесь, используйте `git add ПУТЬ_К_ФАЙЛУ` для каждого нужного файла.

Если Git просит логин — войдите через браузер, как предложит программа. Если `nothing to commit` — у вас пока нет сохранённых изменений; это не обязательно ошибка.

## 9. Создать Pull Request (PR): это и есть сдача задания

1. Откройте **свой Fork**: `https://github.com/ВАШ_ЛОГИН/asu-cloud-platform`.
2. После Push обычно появляется кнопка **Compare & pull request**. Нажмите её. Если нет — вкладка **Pull requests** → **New pull request** → **compare across forks**.
3. Проверьте **base repository = MatveyRuchkin/asu-cloud-platform**, **base = dev**. Справа **head repository = ВАШ_ЛОГИН/asu-cloud-platform**, **compare = feature/НОМЕР**.
4. Напишите понятное название работы.
5. Заполните шаблон Pull Request. В описании обязательно **на отдельной строке**:

```text
Closes #НОМЕР
```

6. Ниже напишите: что сделали, как проверить, какие вопросы остались, какие тесты запускали.
7. Нажмите **Create pull request**. Сохраните ссылку на PR и отправьте её в комментарий к своей Issue.
8. Дождитесь комментариев проверяющего. Если попросили исправить — исправьте в **той же ветке**, снова `git add` → `git commit` → `git push`. PR обновится автоматически.
9. **Не нажимайте Merge самостоятельно**, если вы не назначены проверяющим. После принятия в `dev` задача может пока не закрыться автоматически — руководитель или reviewer подтвердит итоговое состояние.

## 10. Если что-то сломалось

| Ситуация | Что сделать |
| --- | --- |
| GitHub не открывает Issue | Проверьте, что вошли в нужный аккаунт; откройте ссылку с сайта |
| После «беру» нет Assignees | Обновите страницу; прочитайте ответ бота; сообщите PM GitHub-ник и номер Issue |
| `git` или `node` не найден | Перезапустите терминал; проверьте установку соответствующей программы |
| Ошибка при clone | Убедитесь, что форк создан, и заменили ВАШ_ЛОГИН |
| Не находится ветка dev | Выполните `git fetch upstream dev`, затем создавайте ветку |
| OpenCode просит оплату | Не вводите карту. Выберите доступную бесплатную модель или другой сервис |
| Нейросеть предлагает создать новый репозиторий | Откажитесь: мы работаем в существующем `asu-cloud-platform` |
| Не знаете, что написать в PR | Попросите помощника составить описание по реально изменённым файлам и проверкам |

## Если у вас есть доступ Write

Вы можете вместо fork создать отдельную ветку прямо в общем репозитории: см. [короткие команды в CONTRIBUTING.md](../CONTRIBUTING.md#если-вы-получили-права-write-работа-без-fork).
Это **не** разрешает изменять `main` или `dev` напрямую. Результат всё равно отправляется через Pull Request в `dev` и проходит проверку.
Write для выполнения своей задачи не обязателен: путь с fork, описанный выше, тоже правильный.
