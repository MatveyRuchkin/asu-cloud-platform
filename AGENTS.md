# AGENTS.md — правила для Codex, ChatGPT и разработчиков

Это **один общий проект**, не создавайте новый проект внутри репозитория. **До работы** прочитайте README.md, CONTRIBUTING.md, docs/requirements.md, docs/architecture.md, docs/api/openapi.yaml и назначенную Issue.

1. Выполняйте только свою Issue; не меняйте посторонние файлы, не удаляйте чужую работу.
2. Контракт API/OpenAPI является общим источником истины после его утверждения. Путь, метод, JSON-поле, тип, статус ответа и формат ошибки должны совпадать с реализацией frontend и backend.
3. Не меняйте интерфейсы, БД и зависимости самостоятельно — сначала согласуйте в Issue/PR с ответственными.
4. Стиль: frontend TypeScript, единые ESLint/Prettier после настройки; backend Python с type hints, Ruff и pytest после настройки. Не добавляйте фреймворки без Tech Lead.
5. Не добавляйте пароли, токены, реальные персональные данные или .env. Только .env.example.
6. Не коммитьте сгенерированные большие файлы, папки node_modules, виртуальные окружения и логи.
7. Пишите в PR: что сделано, какие файлы затронуты, как проверить, что осталось незавершённым.
8. Если тесты не удалось запустить — честно укажите причину. Не утверждайте, что всё работает, без проверки.
9. Изменения через feature/<issue-number> от dev → Pull Request в dev → ревью → только затем merge. Main = стабильная версия.

## Промпт для Codex
> Проанализируй текущий репозиторий и GitHub Issue №<номер>. Выполни только эту задачу. Сначала прочитай AGENTS.md, CONTRIBUTING.md и OpenAPI. Покажи короткий план, список затрагиваемых файлов, зависимости и риски несовместимости. Не меняй общие API, JSON-поля, БД или архитектуру без согласования. Внеси минимальные изменения, напиши проверки и инструкции запуска. В конце перечисли изменённые файлы, результат тестов и ограничения.
