# ASU Team Bot — Cloudflare Free

Самостоятельный Telegram-координатор в общем репозитории. Состав и роли берутся из `site/team.json` в GitHub, второй список участников не создаётся. Backend, Frontend, OpenAPI, сайт и workflows платформы не изменяются.

Стек: TypeScript, Workers, Telegram webhook, D1, Queues, Cron, Workers AI. VPS, Docker, постоянно работающий процесс и polling не нужны. Yandex выключен по умолчанию и используется только после явного включения владельцем.

## Возможности

- Все команды: `/start`, `/help`, `/mytask`, `/status`, `/ask`, `/blocker`, `/blockers`, `/team`, `/report`, `/whoami`, `/settings`.
- Администратор проверяет личность и подтверждает заявку. Выбор имени не даёт доступ. Роли выводятся из актуальных данных команды.
- GitHub REST: персональная Issue, связанные PR, проверки/Actions, ожидающие ревью, последние замечания и ссылки. Статусы и задачи не расходуют ИИ.
- Вопросы получают ограниченный контекст из GitHub; факты и предположения различаются. Обычный текст обрабатывается как вопрос.
- Блокеры: ответственный, согласие на передачу описания, четыре кнопки ответа, уведомление автора, дедупликация активной зависимости, одно напоминание и эскалации.
- Отчёт руководителя ограничен его областью; сводки участников приходят отдельными сообщениями. Отсутствие PR не трактуется как бездействие.
- Отключение пользователя, удаление данных, ограничения запросов и ИИ, сохранение заданий при сбоях.

## Как устроена обработка

Webhook проверяет секрет и личный чат, атомарно сохраняет `update_id`, минимальный payload и задание в D1. Только затем ставит ссылку на задание в Queue и отвечает Telegram. Ошибка записи/очереди возвращает 503; Telegram повторяет запрос. LLM не запускается в HTTP-обработчике или `waitUntil`.

Consumer берёт задание с арендой в D1. Повторная доставка очередью не повторяет готовое задание. Ответы сохраняются в outbox с постоянными ключами и отправляются отдельными заданиями. Cron каждые 15 минут восстанавливает задания и уведомления, а также запускает напоминания. D1 сохраняет источник задания дольше 24 часов хранения сообщений Queue Free.

Telegram `sendMessage` не поддерживает ключ идемпотентности. При тайм-ауте нельзя доказать, дошло ли сообщение: оно получает состояние `uncertain`, не удаляется и не пересылается автоматически. Администратор уточняет результат и при необходимости подтверждает повтор. Таким образом бот не выдаёт неопределённую доставку за успешную и не скрывает записи об ошибках.

## Границы MVP

Только личные чаты. GitHub только читает. Показаны до двух связанных PR и до 50 проверок/запусков на PR с явным предупреждением о сокращении. Длительные сбои и исчерпание общих квот аккаунта задерживают обслуживание; бесплатная инфраструктура не даёт гарантии непрерывной доставки. Автоматического перехода на платный план или провайдера нет.

Схема обработки согласий, тесты и архитектура перенесены из первоначального прототипа. Python-версия не входит в итоговый код.
