# Тест-кейсы для регистрации и входа (QA-02)

Назначение: подготовить и проверить сценарии регистрации и входа, а также тестовые данные для UI.  
Контракт: `docs/api/openapi.yaml`  
API префикс: `/api/v1`

## Список сценариев

| № | Название | Метод | Эндпоинт | Тип | Шаги | Ожидаемый результат |
|---|---|---|---|---|---|---|
| 1 | **Регистрация. Успешный кейс** | `POST` | `/api/v1/auth/register` | Позитивный | 1. Отправить запрос с валидными полями: `email`, `password` (>= 8 символов), `display_name` (>= 2 символа), валидный `university_id` в формате UUID. | `201 Created`. Тело ответа соответствует схеме `User`: присутствуют `id` (UUID), `display_name`, `university_id`. Поля `faculty`, `course` могут быть `null`. |
| 2 | **Вход. Успешный кейс** | `POST` | `/api/v1/auth/login` | Позитивный | 1. Отправить запрос с `email` и `password` пользователя, ранее успешно зарегистрированного. | `200 OK`. Тело ответа соответствует схеме `Token`: присутствуют `access_token` (строка), `token_type` = `bearer`. |
| 3 | **Регистрация. Пустые обязательные поля** | `POST` | `/api/v1/auth/register` | Негативный | 1. Отправить запрос с пустыми или отсутствующими обязательными полями: `email`, `password`, `display_name`, `university_id`. | `400 Bad Request`. Ответ соответствует схеме `Error`: должны присутствовать поля `code` и `message`. |
| 4 | **Регистрация. Невалидный email** | `POST` | `/api/v1/auth/register` | Негативный | 1. Отправить запрос с `email`, не соответствующим формату email (например: `test.user`, `user@`, `@example.com`). | `400 Bad Request`. Ответ соответствует схеме `Error`: должны присутствовать поля `code` и `message`. |
| 5 | **Регистрация. Короткий пароль (< 8 символов)** | `POST` | `/api/v1/auth/register` | Негативный | 1. Отправить запрос с `password` длиной менее 8 символов (например: `Pass123`). | `400 Bad Request`. Ответ соответствует схеме `Error`: должны присутствовать поля `code` и `message`. Учитывать ограничение `minLength: 8` из `RegisterRequest`. |
| 6 | **Регистрация. Невалидный формат university_id (не UUID)** | `POST` | `/api/v1/auth/register` | Негативный | 1. Отправить запрос с `university_id`, не соответствующим формату UUID (например: `12345`, `not-a-uuid`, пустая строка). | `400 Bad Request`. Ответ соответствует схеме `Error`: должны присутствовать поля `code` и `message`. |

## Способ повторить проверку

### Вариант 1. API-проверка (рекомендуемый, доступен по контракту)
1. Открыть источник истины: `docs/api/openapi.yaml`
2. Использовать базовый URL: `http://localhost:8000/api/v1` (согласно `servers` в OpenAPI)
3. Взять нужный блок запросов из `tests/fixtures/auth-samples.json`
4. Отправить запросы с помощью любого HTTP-клиента:
   - `curl`
   - `Postman`
   - `Insomnia`
   - `Bruno`
   - `HTTPie`

**Примеры (curl):**

Успешная регистрация:
```bash
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"maria.ivanova.test@example.com","password":"StrongPass123","display_name":"Мария Иванова","university_id":"b7f62c8a-9e42-4d71-b803-02ab7d94e861"}'
```

Успешный вход:
```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"maria.ivanova.test@example.com","password":"StrongPass123"}'
```

Проверка невалидного `university_id`:
```bash
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"dmitry.smirnov.test@example.com","password":"StrongPass123","display_name":"Дмитрий Смирнов","university_id":"12345"}'
```

### Вариант 2. UI-проверка
В данный момент **невозможна**. После появления UI-форм (`frontend/`) нужно повторить те же сценарии через интерфейс, используя те же тестовые данные из `tests/fixtures/auth-samples.json`, сверяя результаты с ожидаемыми из таблицы выше.
