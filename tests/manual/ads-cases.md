Тестовые данные: data/demo/ads.json
Проверяемая операция: создание объявления (POST /ads, когда API доступен).

Поля и ограничения

Схема, полученная от разработчика (требует окончательного согласования):

|Поле         |Обязательное|Ограничения                        |
|-------------|------------|-----------------------------------|
|`category`   |Да          |Строка                             |
|`title`      |Да          |Строка длиной от 3 символов        |
|`description`|Да          |Строка длиной от 1 символа         |
|`price_rub`  |Нет         |Целое число >= 0 либо `null`       |
|`image_url`  |Нет         |Строка с корректным URI либо `null`|

Внимание: в опубликованном черновике OpenAPI может использоваться category_id вместо category. Перед API-тестированием нужно подтвердить окончательный контракт у Лаврецкого Константина и Михаила Косачева. Не менять контракт самостоятельно.

Тестовые сценарии

Все сценарии выполняются независимо. Для позитивных проверок использовать соответствующий объект из ads.json; для негативных — копию первого объекта с указанным изменением.

|ID    |Сценарий и действия                                             |Ожидаемый результат                                                                |
|------|----------------------------------------------------------------|-----------------------------------------------------------------------------------|
|ADS-01|Отправить первое объявление без изменений                       |Объявление создано, успешный HTTP-статус по контракту, возвращены корректные данные|
|ADS-02|Отправить объявление №9 с `price_rub: 0`                        |Объявление создано; нулевая цена принята                                           |
|ADS-03|Отправить объявление №10 с `price_rub: null` и `image_url: null`|Объявление создано; `null` в необязательных полях принят                           |
|ADS-04|Удалить `category` из тела запроса                              |Ошибка валидации, объявление не создано                                            |
|ADS-05|Удалить `title` из тела запроса                                 |Ошибка валидации, объявление не создано                                            |
|ADS-06|Установить `title: "AB"`                                        |Ошибка валидации: название короче 3 символов                                       |
|ADS-07|Установить `description: ""`                                    |Ошибка валидации: описание пустое                                                  |
|ADS-08|Установить `price_rub: -1`                                      |Ошибка валидации: цена отрицательная                                               |
|ADS-09|Установить `price_rub: 12.5`                                    |Ошибка валидации: цена не целое число                                              |
|ADS-10|Установить `image_url: "not-a-url"`                             |Ошибка валидации: некорректный URI                                                 |
|ADS-11|Удалить оба необязательных поля `price_rub` и `image_url`       |Объявление создано без этих полей                                                  |

Точные коды успешного ответа и ошибки следует сверить с утверждённым OpenAPI-контрактом, не предполагать их заранее.

Самостоятельная проверка

Проверено локально при подготовке данных: файл data/demo/ads.json успешно прочитан стандартным JSON-парсером Python (python -m json.tool); содержит 10 объектов. Синтаксических ошибок JSON не обнаружено.

Проверка API: не выполнялась. Доступность работающего API и окончательный контракт не подтверждены. Статус сценариев ADS-01—ADS-11: не запускались. Это блокер для проверки фактического создания объявлений, но не для проверки формата тестовых данных.

Как повторить

1. Открыть корень репозитория в терминале.
2. Выполнить python -m json.tool data/demo/ads.json — команда должна завершиться без ошибок.
3. При наличии Python выполнить python -c "import json; a=json.load(open('data/demo/ads.json', encoding='utf-8')); assert isinstance(a


list) and len(a)==10; print('OK: 10 ads')".
4. После утверждения схемы и запуска API отправлять каждый объект на POST /ads согласно требованиям авторизации и формату из OpenAPI. Для негативных сценариев менять копию объекта, не изменяя исходный ads.json.
5. Записать фактический HTTP-статус, тело ответа и результат для каждого сценария; при недоступности API оставить отметку «блокер» и сообщить лиду.
